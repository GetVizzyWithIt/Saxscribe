How well the transcriber does, and where it goes wrong. The first four sections compare setups (which separator, where the sax-rest cuts come from, which note finder) on the same answer keys. The charts below them follow the default pipeline over time.

Where each record stands

Note F1 with today’s default setup: a note counts when its start is within 50 ms, its pitch within 50 cents and its end within 20% (mir_eval). The tick is the v1 target (80 alone, 60 in a band). Sax found: share of the key’s notes we wrote. Sax purity: share of our notes the key has. Key heard: share of the answer key’s notes whose pitch the recording confirms, so low means the key itself is less sure.

Setups compared

Each record on each setup, latest run. The shading is the difference from the default setup on that record: blue better, red worse, full colour at 10 points. ▼ loses sax marks a setup that finds at least 3 points fewer of the key’s notes than the default (or, where only that was measured, 3 points less onset recall), whatever its F1: those are real notes gone. † key may favour this model marks a score on an answer key that was built partly with that model, so it is not a clean win. Where the notes go

Top bar: every note in the answer key, sorted by what happened to it. Bottom bar: every note on our sheet, sorted by where it came from. The two bars share colours where it is the same error seen from each side: a merged repeat in the key is a split note on ours; a missed note in the key is an extra one on ours. Hidden notes are still in notes.json, only off the sheet.

Along the record

One column per bar of the answer key. Found: share of the bar’s key notes we wrote (darker is more; grey is a rest in the key). Hidden: key notes tagged not sax, or a bar mostly inside a sax-rest cut. Extra: notes of ours the key does not have. Quiet passages a setup throws away show as a run of light Found cells with Hidden marks under them.
